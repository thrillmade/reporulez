## 2026-09-15 14:31 - reporulez#71 ask B: check + reusable workflow that fails when a repo's dependabot.yml doesn't target dev

**Reasoning:** GitHub reads .github/dependabot.yml only from a repo's default branch and there is no org-level dependabot setting, so nothing org-wide stopped a repo's dependency-bump PRs from opening against main forever -- this already happened for real (clud-bug#328: main drifted 22 commits ahead of dev in 3 weeks, a 16-file conflict lane) and is still live today on reporulez's own default branch and on both thrillmade/clud-bug#340 and thrillmade/clud-bug-app#129's unmerged base state, used here as control-test fixtures. bin/check-dependabot-target.sh checks a file, a single repo (--repo, via gh api against the default branch), or a whole org (--all, mirroring bin/audit.sh's enumeration); the reusable workflow_call workflow lets any repo adopt it as a per-PR gate with a 2-line wrapper. Exit-code taxonomy (0 clean / 1 real violation / 2 couldn't-even-check) mirrors bin/validate-ruleset.sh's, chosen specifically so 'examines nothing' (missing file, unparseable YAML, zero repos enumerated) can never read as exit 0 -- reporulez#71's own words for the recurring defect class. That guard was mutation-tested by hand (neutering the zero-repos die() and the no-updates early-exit, confirming the suite goes red both times, then reverting) rather than asserted.

**Alternatives considered:** Fold every --all-mode outcome (missing file, parse error, wrong target-branch) into a single exit-1 'violations found' bucket instead of aborting the whole org scan on the first bad repo -- rejected because bin/audit.sh's own precedent is to continue past a per-repo GET failure and report at the end, and an org-wide audit that dies on the first non-conformant repo out of dozens is far less useful than one that reports all of them. Treat a repo with NO dependabot.yml at all as a silent skip (not a violation) in --all mode -- rejected: reporulez#71 says explicitly that a check finding no dependabot.yml must not exit 0, and every templates/dependabot/*.yml this repo ships is something a managed repo is expected to install, so absence is itself worth surfacing, not hiding.

**Implications:**
- Fixing reporulez's own live-violating .github/dependabot.yml is NOT included in this change: PRs that edit dependabot.yml must target main directly (GitHub reads it only from the default branch), and this PR targets dev per reporulez#71's own ask -- that fix is a separate main-targeted follow-up, noted in tests/fixtures/dependabot/real-reporulez-missing-target.yml's header. Consuming repos must add a 2-line wrapper workflow to adopt the check (nothing forces adoption org-wide yet, same limitation AGENTS.md already documents for every other reporulez mechanism). The reusable workflow checks out reporulez at whatever ref invoked it (parsed from github.workflow_ref) rather than a hardcoded SHA pin, since the script lives in the same repo as the workflow calling it.
